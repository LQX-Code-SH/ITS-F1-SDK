# INREII F2 热成像设备二次开发接口文档

> 本文档基于官方安卓应用 `INREII-release-87.apk` 逆向分析整理（反编译源码位于 `jadx_out/`，解包资源位于 `apk_extracted/`）。
> 设备方案为 **艾睿光电（InfiRay）**，应用包名 `com.infiray.outdoor.wifiapp`，设备控制子应用包 `com.infiRay.xwild`。

---

## 1. 应用整体架构

INREII 官方 App 是一个「调度壳 + 三个子应用」的 Flutter/Native 混合工程：

```
INREII App (com.infiray.outdoor.wifiapp, Flutter)
    │  USB 插入设备后按 productName 分发：
    ├── XWild 子应用 (com.infiRay.xwild)      ← USB 热成像单目镜（XW2/WL19/WL13/Sirius/WP09）
    ├── XLink 子应用 (com.infiRay.xlink)      ← USB 热成像（FX3/Xtherm/Camera/XP09/CBM9002 等）
    └── Seek  子应用 (com.infiRay.seek)       ← DR200/Rover 系列热成像瞄
```

分发逻辑（`com/iraytek/xinfrared/wifi_app/MainActivity.java`）：

| USB productName 包含 | 启动 Intent | 说明 |
|---|---|---|
| `Sirius` / `WP09` / `XWild` / `WL19` / `XW2` | `com.infiray.xwild.main` | **F2 属于此类（XWild 家族，XW2 同硬件方案）** |
| `DR200` / `Rover` | `com.infiray.seek.main` | Rover/DR200 |
| 其他 | `com.infiray.xlink.main` | XLink/FX3 系 |

F2 的通信通道有两条：
1. **USB（UVC 协议）**：视频流 + 所有参数控制命令（核心）
2. **BLE（蓝牙低功耗）**：激光测距控制与测距数据回传（可选，配套功能）

## 2. USB 设备识别（重要）

`res/xml/device_filter.xml`：

| vendor-id | product-id | 十六进制 | 说明 |
|---|---|---|---|
| 13428 | 24597 | **VID 0x2B74, PID 0x6015** | InfiRay 热成像 UVC 设备 |

`deviceClass == 239 && deviceSubclass == 2`（Miscellaneous / Common Class，即标准 UVC 复合设备）。

## 4. 核心控制接口：`com.serenegiant.usb.UVCCamera`

F2 的所有控制命令通过 InfiRay 定制版 UVCCamera 库（`libUVCCamera.so`）发出，底层为 UVC 扩展控制请求。
Java 侧完整公开 API（节选自 `jadx_out/sources/com/serenegiant/usb/UVCCamera.java`）：

### 4.1 生命周期
```java
UVCCamera camera = new UVCCamera();
camera.open(usbControlBlock);            // USBMonitor.UsbControlBlock
camera.setPreviewSize(w, h, format, fps, pixelFormat, bandwidth, model);
camera.setPreviewDisplay(Surface/SurfaceHolder/SurfaceTexture);
camera.startPreview();
camera.stopPreview();
camera.destroy();
camera.close();
```

### 4.2 帧与图像数据
```java
camera.setFrameCallback(IFrameCallback cb, int pixelFormat); // 实时帧回调
camera.getByteArrayPicture(byte[] buf);      // 读取当前帧图像数据（用于拍照）
```

### 4.3 热成像专属接口（InfiRay 扩展，普通 UVC 相机没有）

| 方法 | 功能 |
|---|---|
| `startTemp()` / `stopTemp()` | 启动/停止测温（`nativeStartStopTemp`） |
| `setTemperatureCallback(ITemperatureCallback cb)` | 温度回调，`onReceiveTemperature(float[])`（全屏温度数组，用于画点/框测温） |
| `setORCallback(IORCallback cb)` | 目标识别温度回调 `onReceiveTemperature(int[])` |

| `setFps(int)` | 帧率设置 |

| `isCorrect()` | 设备参数校验 |

### 4.4 `setZoom()` 魔数命令表（重要！）

该设备固件把 **UVC Zoom 控制通道当作扩展命令通道**，`setZoom(值)` 中值的高位是命令码。
App 实际使用（`MainActivity_KT.java`）：

| setZoom 值 | 十六进制 | 含义 |
|---|---|---|
| `32768` | 0x8000 | 快门校正（配合 `whenShutRefresh()`；自动快门定时器每 60s 调用一次） |
| `32901` | 0x8085 | 测距模式关闭（jgtab=0） |
| `32902` | 0x8086 | 测距模式开启（jgtab=1，显示距离分划） |
| `34816` | 0x8800 | 图像模式 1（视场/增稳档位，配合调色板 0/5） |
| `34817` | 0x8801 | 图像模式 2（调色板 1/6） |
| `34818` | 0x8802 | 图像模式 3（调色板 2/7） |
| `34821` | 0x8805 | 图像模式（近摄档） |
| `34822` | 0x8806 | 图像模式 |
| `34823` | 0x8807 | 图像模式 |
| `35073` | 0x8901 | HD+ 超清模式（768×580） |

调色板索引（`changePalette`）：
```
0 = 白热 (white_hot)   1 = 黑热 (black_hot)
2 = 红热 (red_hot)     3 = 铁红/彩虹 (iron_rainbow)
5/6/7 = 各图像模式下的冷热变体（由 App 在切换图像模式时联动设置）
≥6 = 自定义调色板（配合 setUserPalette 传入 768 字节）
```

## 5. 标准视频栈（推荐上层封装）

App 不直接操作 UVCCamera，而是通过封装层 `com.infiRay.xwild.utils.UVCCameraHandler`：

```java
// 创建（内部单例）
UVCCameraHandler handler = UVCCameraHandler.createHandler(
        activity, uvcCameraTextureView,
        parentId, width, height, format,
        ITemperatureCallback);            // 也可再传 maxFps, bandwidth, type

handler.startPreview(Surface);            // 开始预览
handler.captureStill(String filePath);    // 拍照（PNG 保存到 DCIM/XWild）
handler.watermarkOnOff(int onOff);        // 水印开关
handler.startRecording() / stopRecording(); // 录像（MediaMuxer，MPEG4）
handler.close();
```
目录：照片 `DCIM/XWild/`（XW2 机型单独 `DCIM/XW2/`）。

辅助 UI 组件：`UVCCameraTextureView`（含测温叠加、双指缩放）、`AbstractUVCCameraHandler`。

## 6. BLE 激光测距协议

F2 支持通过蓝牙连接测距模块（设备广播名包含 **`Chipsea_BLE`**）。
实现在 `com.infiRay.xwild.ble.BLEManager`。

### 6.1 GATT 定义

| 项目 | UUID |
|---|---|
| Service | `0000FFF0-0000-1000-8000-00805F9B34FB` |
| Read/Notify 特征 | `0000FFF1-0000-1000-8000-00805F9B34FB` |
| Write 特征 | `0000FFF2-0000-1000-8000-00805F9B34FB` |

流程：扫描 → 过滤名字含 `Chipsea_BLE` → connectGatt → 请求 MTU（`requestMtu(0x100)` = 256）→ 订阅 Notify。

### 6.2 帧格式

```
AE A7 | LEN | CMD_H CMD_L | DATA... | CHK | BC BE
帧头        长度   命令字        数据      校验和  帧尾
```
- 校验：从 LEN 起至 DATA 末尾按字节累加的低 8 位（实测：`AE A7 05 00 40 01` → 05+00+40+01 = 0x46 ✓）

### 6.3 已知命令

| 方向 | 帧 | 含义 |
|---|---|---|
| App → 设备 | `AEA70500400146BCBE` | 激光测距开启（switch_laser ON） |
| App → 设备 | `AEA70500400045BCBE` | 激光测距关闭（switch_laser OFF） |
| App → 设备 | `AEA704000E12BCBE` | BLE 连接成功后发送（握手/查询） |
| 设备 → App | 8 字节任意帧 | 连接确认（收到后显示测距 UI，显示 "< 4.0m"） |
| 设备 → App | `AE A7 17 00 85 ...` | **测距结果帧**，见下 |

### 6.4 测距结果帧解析（偏移以帧字符串计）

帧示例：`AE A7 17 00 85 xx xx LL LL LL xx HH HH HH ... BC BE`
- 从帧头 `AE A7 17 00 85` 算起：
  - **直线距离**：字节偏移 21~26 处 3 字节（HEX）→ `Integer.parseInt(hex,16) / 10.0` = 米
  - **水平距离**：字节偏移 33~38 处 3 字节（HEX）→ 同上 / 10.0 = 米
- 距离 < 4.0 m 时设备回 8 字节短帧，App 直接显示 `< 4.0m`

## 10. 二次开发建议

1. **最简方案**：把 F2 当作标准 UVC 相机（VID 0x2B74/PID 0x6015）用任意 UVC 库（如 AndroidUVCCamera/saki4510t 原版）拉 **MJPEG 384×292@50fps** 流即可出图；测温、调色板、快门等高级功能必须使用 InfiRay 定制 `libUVCCamera.so`（本 APK 内可直接提取 `libUVCCamera.so + libusb100.so + libuvc.so + libjpeg-turbo1500.so` 及对应 Java 类 `com.serenegiant.usb.*`）。
2. **命令复用**：所有控制命令走 `setZoom()` 魔数 + 扩展方法（见第 4.3/4.4 节），直接照抄即可。
3. **测温叠加**：注册 `ITemperatureCallback` 后把 `float[]` 交给自定义渲染层；测温需先 `startTemp()`，修改发射率后调用 `whenChangeTempPara()`。
4. **BLE 测距**：仅当需要激光测距显示时使用，协议见第 6 节。
5. **分辨率注意**：切 HD+（768×580）前必须先 `setZoom(35073)` 通知固件。
6. **反编译源码位置**：`jadx_out/sources/com/serenegiant/usb/UVCCamera.java`（SDK 核心）、`jadx_out/sources/com/infiRay/xwild/ui/MainActivity_KT.java`（8000+ 行，所有功能调用示范）、`jadx_out/sources/com/infiRay/xwild/ble/BLEManager.java`。

# 附录 B：INREII F1 实测接口（Linux USB 直连验证）

> F1 与 F2 通信栈完全不同。F1 走 **Vendor-Specific Bulk 协议**（非标准 UVC），
> 对应官方 App 的 **XLink 子应用**（productName 含 "Camera" 命中 `com.infiray.xlink.main`，
> 使用 `com.serenegiant.usbxlink.*` + `libUVCCameraabc.so`）。

## B.1 USB 描述符（实测 lsusb）

```
ID 04b4:000a  Cypress Semiconductor Corp. Thermal Camera
iManufacturer: Inlumen Technologies Co., Ltd.   iSerial: C502301-ABL0459
接口0 (协议1): 视频/数据流
  alt 0: 无端点     alt 1: EP2 IN (Bulk,512B) + EP6 OUT (Bulk,512B)
接口1 (协议0): 命令通道
  EP1 IN (Bulk,64B) + EP1 OUT (Bulk,64B)
```
注意：该 PID 不在 App 的 device_filter.xml（只有 0x2B74:0x6015 和 0x04B4:0x00F8）中，
App 是程序内枚举按 productName 匹配的，Linux 下需自行动 claim 接口。

## B.2 数据流结构（实测逆向）

- 切换接口 0 到 alt 1 后 **EP2 IN 自动出流，无需启动命令**
- 流由 14348 字节的块组成，每块 = 12 字节块头 + 14336 字节数据
- 每 **7 块 = 1 帧**，帧 = 100436 字节；帧率 25fps（块间约 5.7ms，ms 级时间戳可证）
- 每块数据 14336B = **256 像素 × 28 行**
- **帧必须从 TYPE=0x01 的块开始装配**，块顺序按类型循环 01→1D→39→55→71→8D→A9
  （⚠️ 从任意块锚定会导致 7 块错位、图像被切割成不连续的条带——已通过接缝连续性分析证实）
- **图像 = 前 192 行 = 256×192 Y16 小端**；末尾第 192~195 行为遥测/附加行（含标记值，非像素，
  与 xlink 代码 `(mHeight-4)*mWidth+10` 吻合）
- 验证方法：帧间差分可见连续手掌轮廓（接缝比 0.70 vs 错误排列 ≈3.0）

块头 12 字节：
```
0C | STAT | TS[3] (u24 LE 毫秒时间戳) | 00 01 00 | TYPE | 00 00 00
     │        │                         │         └ 类型字节，7块周期循环:
     │        │                         │           01,1D,39,55,71,8D,A9 (+0x1C)
     │        │                         └ 固定
     │        └ 上位字节(随时间缓慢递增, 与 TS 拼成 24bit)
     └ 状态: 0x8C/0x8D/0x8E/0x8F (0x8D 疑似帧起始标记)
```

## B.3 图像数据处理（重要）

EP2 IN 读出的是**未经校正的原始 Y16**（值域 0~65535，实测场景均值约 6800）：
- 含大量固定图案噪声（列/行条纹）→ 官方 App 经 libthermometry.so 做两段式校正后显示
- 第 52~55 行（0 基）为特殊行（多帧均为 0x0000），与 xlink 代码中
  `(mHeight-4)*mWidth+10` 的"-4 行"处理吻合
- 拍照 PNG 前 App 会先做增益校正 + AGC + 细节增强（libSimplePictureProcessing.so）

Linux 快速验证（已验证可见场景轮廓）：
```python
img -= img.mean(axis=0, keepdims=True)   # 去列固定噪声
img -= img.mean(axis=1, keepdims=True)   # 去行固定噪声
# 再做百分位拉伸/直方图均衡即可看到场景
```

## B.4 命令通道（接口1，待深入）

## D.4 主机端处理（不发 USB 命令）

反汇编证实以下功能为**纯主机端实现**（F1 设备只出原始 Y16）：

1. **伪彩调色板**：`UVCPreviewIR::changePalette` 仅存储色板号到成员变量，
   渲染管线用 LUT 把 Y16 映射为 RGB（9 色板 = 9 张主机端 LUT）
2. **测温**：`thermometryT4Line`（libthermometryabc.so）逐行计算——T4 即
   斯蒂芬-玻尔兹曼四次方辐射公式拟合；输入 Y16 + 标定参数
3. **温度标定参数来自帧尾**：`getByteArrayTemperaturePara` 直接从帧缓冲区
   `(w×(h-4)+10)×2` 字节偏移拷贝 64 字节参数块（发射率/反射温/标定系数等），
   每帧都随流下发，无需单独请求
4. **快门触发**：`whenShutRefresh` 仅置标志位，预览线程检测后发 zoom 命令 0x8000
5. **R+ 超分**：TNN 模型（GAN 降噪+超分）主机端推理

## D.5 Linux 端最小实现路径

## E.2 测温公式（自校准 T⁴，实测室温场景 6.7~38.3℃ 合理）

```
T(℃) = (T_shutter + 273.15) × (raw / shutter_raw)^0.25 − 273.15
shutter_raw = 遥测行0 word0（设备每帧自报的快门参考计数）
```
依据: libthermometry 的 T⁴ 辐射律 + CalcFixRaw 多项式 + p30=25.0 标定温。
精确绝对精度还需两点标定（冰水 0℃ / 体温 ~33℃）。

## E.4 控制通道最终结论

F1 固件（Cypress FX2, 04b4:000a）**不响应 EP0 UVC 类请求**（GET=STALL, SET=超时，
全空间厂商命令探测仅 0x08/0x0A/0xA0 有响应=传感器 FIFO）。结论：
- **调色板/测温/AGC/超分全部主机端实现**（changePalette 只存索引已证实）
- 设备内自动快门（流中可见全帧均匀的快门帧，作为 NUC 暗场参考）
- 固件升级走 bulk（Java 层: 接口0 + `{1,6,0,0,0,0,0,0}` 初始化命令）
- 二次开发只需: 读流 + 主机端处理，**无需任何控制命令**

## F.1 标定程序

## F.2 标准作业流程（SOP）

| 步骤 | 操作 | 要点 |
|---|---|---|
| 1 准备 | 冰水混合物一杯（0℃，带冰碴搅匀静置 1min）+ 热水一杯（45~65℃），温度计实测热水温度记录 | 水的发射率 ≈0.96，贴近黑体 |
| 2 冷点 | 运行 `sudo python3 temp_calibration.py` → 选 `1` → 镜头距冰水液面 3~5cm → 画面稳定（≥5s）后回车 | 镜头勿入水/勿起雾；液面无浮渣 |
| 3 热点 | 选 `2` → 输入温度计实测值 → 镜头对热水液面 → 稳定后回车 | 热水持续轻微搅动，读温度计与采集同步 |
| 4 保存 | 选 `3` → 生成 `temp_calib.json`，打印修正系数 a/b | 两点模型读数差须 ≥3℃，否则无效 |
| 5 验证 | 选 `4` 对任意目标，核对修正后读数 | 误差应 ≤ ±2℃ |
| 6 复标 | 更换设备/镜头、环境温度大变（>15℃）、或每 6 个月例行 | 删除 temp_calib.json 即回退未标定状态 |

## F.3 注意事项

1. 标定与设备一一绑定（序列号写入 json 备查），多设备各存一份
2. 测温对象为**液面/高发射率表面**；金属亮面（低发射率）读数偏低属物理现象，需手动设发射率
3. 标定后模型公式：`T真实 = a × [(T_sh+273.15)·(raw/shutter_raw)^0.25 − 273.15] + b`
4. 当前状态：**未标定**（出厂发射率 0.98 + 标定温 25.0℃ 直出，误差约 ±3~5℃）
